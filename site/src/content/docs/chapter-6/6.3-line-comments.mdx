<p className="book-subtitle">Chapter 6 · Tokens That Grow</p>

The two slashes in `// note` currently become errors, and `note` becomes an
identifier. A line comment should stay together. Its text belongs in our
token stream as trivia, and source after the next newline must still be
scanned normally.

A single `/` also has a job: it spells Lox’s division operator. Reading one
slash isn’t enough to choose its kind. As with `!` and `!=`, we’ll inspect
the next character before deciding whether to consume it.

Start from [Section 6.2](/chapter-6/6.2-whitespace/), with your terminal in
**`rlox/`**. All edits belong to **`rlox/crates/syntax/src/lib.rs`**. We’ll
reuse the existing iterator, byte ranges, and source-coverage checks.

## Leave the line ending for whitespace

After consuming `//`, we’ll keep reading until a line feed (`\n`) or EOF.
The comment token includes the slashes and its body. It stops **before** the
line feed so that the existing whitespace arm can consume that character
on the next outer iteration.

Consider this source, written as a Rust string literal to make its line
ending visible:

```rust title="Source with a UTF-8 comment and a CRLF line ending"
"//é\r\nname"
```

`é` occupies two bytes. With a carriage return followed by line feed, our
stopping rule keeps the carriage return in the comment. Only line feed
terminates it, matching the scanner in *Crafting Interpreters*.

```text title="Where the comment ends"
Read / at byte 0                 end = 1
Consume / at byte 1              end = 2
Consume é at byte 2              end = 4
Consume \r at byte 4             end = 5
Inspect \n at byte 5             leave it unread; emit comment
Next outer iteration reads \n    emit whitespace
Then read name                  emit identifier
```

The resulting tokens select these original pieces:

```text title="Retained comment, line feed, and following name"
LineComment  [0, 5)   "//é\r"
Whitespace   [5, 6)   "\n"
Identifier   [6, 10)  "name"
```

The bytes all remain available for source reconstruction. We’re choosing
where to split tokens, rather than removing the comment or line ending.
A lone carriage return does not terminate a comment under this rule.

## Choose between a slash and a comment

Add `Slash` after `RightParen`, and `LineComment` after `Whitespace`, in
`SyntaxKind`:

```diff title="rlox/crates/syntax/src/lib.rs · operator kinds"
     RightParen,
+    Slash,
     Bang,
```

```diff title="rlox/crates/syntax/src/lib.rs · trivia kinds"
     Whitespace,
+    LineComment,
     Error,
```

In `scan`, the outer loop has already consumed the first slash and initialized
its range. Add this arm **inside `match ch`, immediately before the whitespace
arm** beginning `' ' | '\t' | '\r' | '\n'`:

```rust title="rlox/crates/syntax/src/lib.rs · add slash and comment arm"
'/' => {
    if chars.next_if(|&(_, next)| next == '/').is_some() {
        end += 1;
        while let Some((offset, next)) = chars.next_if(|&(_, next)| next != '\n') {
            end = offset + next.len_utf8();
        }
        SyntaxKind::LineComment
    } else {
        SyntaxKind::Slash
    }
}
```

The first [`next_if`](https://doc.rust-lang.org/std/iter/struct.Peekable.html#method.next_if)
tries to consume a second slash. If none matches, the first character’s range
is already correct: return `Slash`. Any nonmatching character remains in
the iterator for the next token. That matters for `/name`, where the name
must not lose its first letter.

A successful match consumes an ASCII slash, so `end += 1` extends the token
by one byte. This also makes `//` at EOF a complete, nonempty comment even
though there is no body to read.

Inside that branch, the second `next_if` accepts any character except line
feed. Each successful read advances `end` using the returned byte offset and
character length. We use that calculation because comment text may contain
multibyte characters. Punctuation, spaces, and additional slashes are ordinary
body characters here; they don’t go through the outer token classification.

The [while let pattern](https://doc.rust-lang.org/book/ch19-01-all-the-places-for-patterns.html#while-let-conditional-loops)
continues only while a consumed pair is returned in `Some`, as in our
identifier scanner.

When line feed fails the predicate, it remains unread. If the source ends
instead, `next_if` returns `None` too. Either way, the inner loop finishes
and returns `LineComment`; the shared code after the match constructs and
pushes its range. The next outer iteration either handles the waiting line
feed or ends the scan.

No import, helper, manifest, or coordinate change is needed. The scanner’s
public signature remains `scan(source: &str) -> Vec<Token>`.

## Check both slash decisions

Append this test **inside the existing `mod tests`, before its closing
brace**. Keep the imports and earlier tests:

```rust title="rlox/crates/syntax/src/lib.rs · append inside mod tests"
#[test]
fn recognizes_single_slashes() {
    assert_eq!(
        scan("/"),
        vec![Token {
            kind: SyntaxKind::Slash,
            range: TextRange::new(TextSize(0), TextSize(1)).unwrap(),
        }]
    );
    assert_eq!(
        scan("/name"),
        vec![
            Token {
                kind: SyntaxKind::Slash,
                range: TextRange::new(TextSize(0), TextSize(1)).unwrap(),
            },
            Token {
                kind: SyntaxKind::Identifier,
                range: TextRange::new(TextSize(1), TextSize(5)).unwrap(),
            },
        ]
    );
}
```

The first assertion checks a failed lookahead at EOF. The second checks a
failed comparison when input remains. In both cases the slash covers only
its own byte.

Follow a Windows-style line ending through both rules. For `//x\r\n`,
where the escapes stand for actual carriage-return and line-feed bytes,
the comment consumes `/`, `/`, `x` and the carriage return. Its stopping
condition is line feed. The outer loop then gives that line feed to the
whitespace rule. The comment range ends at byte 4 and whitespace occupies
`[4, 5)`. Keeping that exact division in mind makes the next test readable.

## Check the comment boundary

Append this test **inside the same module** for our annotated source:

```rust title="rlox/crates/syntax/src/lib.rs · append inside mod tests"
#[test]
fn line_comments_leave_the_line_feed_unread() {
    assert_eq!(
        scan("//é\r\nname"),
        vec![
            Token {
                kind: SyntaxKind::LineComment,
                range: TextRange::new(TextSize(0), TextSize(5)).unwrap(),
            },
            Token {
                kind: SyntaxKind::Whitespace,
                range: TextRange::new(TextSize(5), TextSize(6)).unwrap(),
            },
            Token {
                kind: SyntaxKind::Identifier,
                range: TextRange::new(TextSize(6), TextSize(10)).unwrap(),
            },
        ]
    );
}
```

The expected whitespace token proves the comment didn’t consume the line
feed. The final identifier proves that scanning resumed on the next line.
The two-byte character and carriage return also have precise places in the
comment range.

EOF is another valid way to finish a line comment. Append this test **inside
the same module**:

```rust title="rlox/crates/syntax/src/lib.rs · append inside mod tests"
#[test]
fn line_comments_can_end_at_eof() {
    for source in ["//", "//é", "///"] {
        assert_eq!(
            scan(source),
            vec![Token {
                kind: SyntaxKind::LineComment,
                range: TextRange::new(TextSize(0), TextSize(source.len())).unwrap(),
            }]
        );
    }
}
```

These cases cover an empty body, multibyte text at EOF, and another slash
inside the body. None needs a trailing newline to produce its token.

use rlox_text::{TextRange, TextSize};

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum SyntaxKind {
    LeftParen,
    RightParen,
    Slash,
    Bang,
    BangEqual,
    Equal,
    EqualEqual,
    Identifier,
    Whitespace,
    LineComment,
    Error,
}

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub struct Token {
    pub kind: SyntaxKind,
    pub range: TextRange,
}

pub fn scan(source: &str) -> Vec<Token> {
    let mut tokens = Vec::new();
    let mut chars = source.char_indices().peekable();

    while let Some((start, ch)) = chars.next() {
        let mut end = start + ch.len_utf8();
        let kind = match ch {
            '(' => SyntaxKind::LeftParen,
            ')' => SyntaxKind::RightParen,
            '!' => {
                if chars.next_if(|&(_, next)| next == '=').is_some() {
                    end += 1;
                    SyntaxKind::BangEqual
                } else {
                    SyntaxKind::Bang
                }
            }
            '=' => {
                if chars.next_if(|&(_, next)| next == '=').is_some() {
                    end += 1;
                    SyntaxKind::EqualEqual
                } else {
                    SyntaxKind::Equal
                }
            }
            '/' => {
                if chars.next_if(|&(_, next)| next == '/').is_some() {
                    end += 1;
                    while let Some((offset, next)) = chars.next_if(|&(_, next)| next != '\n') {
                        end = offset + next.len_utf8();
                    }
                    SyntaxKind::LineComment
                } else {
                    SyntaxKind::Slash
                }
            }
            ' ' | '\t' | '\r' | '\n' => {
                while let Some((offset, next)) =
                    chars.next_if(|&(_, next)| matches!(next, ' ' | '\t' | '\r' | '\n'))
                {
                    end = offset + next.len_utf8();
                }
                SyntaxKind::Whitespace
            }
            ch if ch.is_ascii_alphabetic() || ch == '_' => {
                while let Some((offset, next)) =
                    chars.next_if(|&(_, next)| next.is_ascii_alphanumeric() || next == '_')
                {
                    end = offset + next.len_utf8();
                }
                SyntaxKind::Identifier
            }
            _ => SyntaxKind::Error,
        };
        let range = TextRange::new(TextSize(start), TextSize(end))
            .expect("character end follows its start");

        tokens.push(Token { kind, range });
    }

    tokens
}

    fn token_ranges_cover_the_original_source() {
        for source in [

            " \t\r\n",
            "a \t\r\n!= b",

            "2aé_b",

Our handwritten scanner now recognizes a small set of operators, names,
whitespace, and line comments while preserving the whole source. The next
transition will replace its scanning mechanics with Logos and build on these
regression cases to recognize the rest of Lox’s lexical syntax.

[Crafting Interpreters, “Longer Lexemes”](https://craftinginterpreters.com/scanning.html#longer-lexemes)
explains the slash/comment decision. We retain its LF stopping rule and keep
the comment text for the syntax and editor tools we’re building toward.
