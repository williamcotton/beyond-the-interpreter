<p className="book-subtitle">Chapter 11 · Parsing Expressions by Hand</p>

`1 + 2 * 3` and `(1 + 2) * 3` contain the same numbers and operators, but
request different trees. In the first, multiplication belongs inside the
addition's right operand. In the second, grouping puts addition inside
the multiplication's left operand.

```text title="Two source expressions, two shapes"
1 + 2 * 3   → (+ 1 (* 2 3))
(1 + 2) * 3 → (* (group (+ 1 2)) 3)
```

We'll finish our arithmetic parser by giving addition and subtraction a
rule that reads complete multiplicative expressions as its operands.
[Crafting Interpreters explains precedence through this rule hierarchy](https://craftinginterpreters.com/parsing-expressions.html#recursive-descent-parsing).

Start from [Section 11.4](/chapter-11/11.4-parse-factors/), in the **Rust
workspace directory**. The new code goes in the existing parser module;
our AST, operator types, cursor and printer already support the result.

## Let each additive operand finish its factor

The complete grammar for this chapter is:

```text title="Arithmetic recursive-descent rules"
expression → term
term       → factor ( ("+" | "-") factor )*
factor     → unary ( ("*" | "/") unary )*
unary      → "-" unary | primary
primary    → NUMBER | "(" expression ")"
```

The `term` loop has the same shape as `factor`, but calls one level further
down for its operands. For `1 + 2 * 3`, that gives us this sequence:

```text title="The factor on the right completes before addition"
[0..1) 1   [2..3) +   [4..5) 2   [6..7) *   [8..9) 3

left factor reads 1 and stops before +       → 1
term consumes +
right factor reads the whole product 2 * 3   → (* 2 3)
term builds its binary parent                → (+ 1 (* 2 3))
```

That call order implements **precedence**. The additive rule can't build its
parent until the multiplicative rule has finished its operand. It doesn't
need to inspect the source string for a later `*` or rearrange a tree after
construction.

## Add the term loop

In **`rlox/crates/syntax/src/parser.rs`**, inside the `Parser` impl,
**after `expression` and before `factor`**, insert:

```rust title="rlox/crates/syntax/src/parser.rs · insert the additive term rule"
    fn term(&mut self, nesting: usize) -> Result<Expr, ParseError> {
        let mut expr = self.factor(nesting)?;
        let mut height = tree_height(&expr);

        while let Some(token) = self.peek() {
            let op = match token.kind {
                SyntaxKind::Plus => BinaryOp::Add,
                SyntaxKind::Minus => BinaryOp::Subtract,
                _ => break,
            };
            self.bump();
            let right = self.factor(nesting)?;
            let next_height = 1 + height.max(tree_height(&right));
            if nesting + next_height > MAX_NESTING {
                return Err(error_at(token, "expression nesting limit exceeded"));
            }
            expr = Expr::Binary {
                left: Box::new(expr),
                op,
                right: Box::new(right),
            };
            height = next_height;
        }

        Ok(expr)
    }
```

We reuse the [conditional loop and pattern](https://doc.rust-lang.org/book/ch19-01-all-the-places-for-patterns.html)
from the multiplicative rule. The differences express the grammar: select
`Plus` or `Minus`, map to `Add` or `Subtract`, and call `factor` for each
operand. Keeping these two short rules explicit lets us read their
precedence relationship directly.

The old left tree moves into `Box::new(expr)` each time. That makes repeated
subtraction associate to the left:

```text title="Subtraction folds left"
8            → 8
8 - 3        → (- 8 3)
8 - 3 - 1    → (- (- 8 3) 1)
```

The height calculation is also unchanged in meaning. `tree_height` already
handles every `Expr::Binary`, independent of its operator. A completed
factor may itself be a tall tree, so we count both operands and enclosing
`nesting` before constructing the new additive parent. If it would exceed
64 non-leaf nodes along a path, the saved additive token is the error
location. We don't grant each precedence level a separate budget.

In `expression`, change the delegation:

```diff title="rlox/crates/syntax/src/parser.rs · enter the additive level"
     fn expression(&mut self, nesting: usize) -> Result<Expr, ParseError> {
-        self.factor(nesting)
+        self.term(nesting)
     }
```

Check both edits together:

```sh
cargo check -p rlox-syntax
cargo test -p rlox-syntax parser::tests
```

The nineteen existing parser tests should still pass. Without an additive
operator, the new rule simply returns the factor it read. No import, AST,
cursor, helper or existing-test changes are needed.

## Put the hierarchy to work

In `(1 + 2) * 3`, the primary rule enters `expression` after `(`. That inner
call now reaches `term`, which builds the addition and leaves `)` for the
grouping rule. The outer factor can then multiply the completed grouping
by `3`. Parentheses override the ordinary precedence by starting another
expression at the point where a primary belongs.

The token's role also depends on where the grammar reads it. In `1--2`,
`term` consumes the first minus as subtraction. Its right factor enters
`unary`, where the second minus begins negation. The scanner still supplies
two separate minus tokens:

```text title="Binary minus followed by unary minus"
1--2 → (- 1 (- 2))
```

In **`rlox/crates/syntax/examples/parse_expression.rs`**, append these inputs
inside the source array, **after `"8 / é",` and before `] {`**. Keep the
existing entries and result-display loop:

## See what the owned AST leaves out

The first and last new example inputs have different numeric spellings,
spacing and comments, but both print `(+ 1 (* 2 3))`. Our nodes store numeric
values and expression relationships. They don't store those trivia tokens,
number spellings or exact source ranges for each successful node. A
`Grouping` preserves the presence of a group, but not its two delimiter
tokens as source-bearing children.

Malformed input exposes another limitation. For `1 +`, we return a useful
error position, but no tree containing the unfinished addition. An editor
still has that source text and needs a representation it can inspect while
the user is midway through typing it. Our scanner retains the text coverage;
our owned AST hasn't kept all of it or represented the missing child.

We've reached the chapter checkpoint: a small recursive-descent parser for
numbers, grouping, unary negation and arithmetic operators, with explicit
precedence, associativity and failure behavior. The next chapter introduces
lossless syntax trees with Rowan so we can keep concrete source details and
represent incomplete syntax as we build toward editor tooling.

```rust title="rlox/crates/syntax/src/parser.rs · complete resulting file"
use rlox_text::{TextRange, TextSize};

use crate::expr::{BinaryOp, Expr, UnaryOp};
use crate::{SyntaxKind, Token, scan};

const MAX_NESTING: usize = 64;

#[derive(Debug)]
pub struct ParseError {
    pub message: String,
    pub range: TextRange,
}

fn error_at(token: Token, message: &str) -> ParseError {
    let message = if token.kind == SyntaxKind::Error {
        "invalid token"
    } else {
        message
    };
    ParseError {
        message: message.to_owned(),
        range: token.range,
    }
}

fn tree_height(expr: &Expr) -> usize {
    match expr {
        Expr::Number(_) => 0,
        Expr::Grouping(child) => 1 + tree_height(child),
        Expr::Unary { right, .. } => 1 + tree_height(right),
        Expr::Binary { left, right, .. } => 1 + tree_height(left).max(tree_height(right)),
    }
}

pub fn parse(source: &str) -> Result<Expr, ParseError> {
    let mut parser = Parser::new(source);
    let expr = parser.expression(0)?;
    if parser.peek().is_some() {
        return Err(parser.error("expected end of input"));
    }
    Ok(expr)
}

struct Parser<'src> {
    source: &'src str,
    tokens: Vec<Token>,
    current: usize,
}

impl<'src> Parser<'src> {
    fn new(source: &'src str) -> Self {
        let mut tokens = scan(source);
        tokens.retain(|token| {
            !matches!(token.kind, SyntaxKind::Whitespace | SyntaxKind::LineComment)
        });
        Self {
            source,
            tokens,
            current: 0,
        }
    }

    fn expression(&mut self, nesting: usize) -> Result<Expr, ParseError> {
        self.term(nesting)
    }

    fn term(&mut self, nesting: usize) -> Result<Expr, ParseError> {
        let mut expr = self.factor(nesting)?;
        let mut height = tree_height(&expr);

        while let Some(token) = self.peek() {
            let op = match token.kind {
                SyntaxKind::Plus => BinaryOp::Add,
                SyntaxKind::Minus => BinaryOp::Subtract,
                _ => break,
            };
            self.bump();
            let right = self.factor(nesting)?;
            let next_height = 1 + height.max(tree_height(&right));
            if nesting + next_height > MAX_NESTING {
                return Err(error_at(token, "expression nesting limit exceeded"));
            }
            expr = Expr::Binary {
                left: Box::new(expr),
                op,
                right: Box::new(right),
            };
            height = next_height;
        }

        Ok(expr)
    }

    fn factor(&mut self, nesting: usize) -> Result<Expr, ParseError> {
        let mut expr = self.unary(nesting)?;
        let mut height = tree_height(&expr);

        while let Some(token) = self.peek() {
            let op = match token.kind {
                SyntaxKind::Star => BinaryOp::Multiply,
                SyntaxKind::Slash => BinaryOp::Divide,
                _ => break,
            };
            self.bump();
            let right = self.unary(nesting)?;
            let next_height = 1 + height.max(tree_height(&right));
            if nesting + next_height > MAX_NESTING {
                return Err(error_at(token, "expression nesting limit exceeded"));
            }
            expr = Expr::Binary {
                left: Box::new(expr),
                op,
                right: Box::new(right),
            };
            height = next_height;
        }

        Ok(expr)
    }

    fn unary(&mut self, nesting: usize) -> Result<Expr, ParseError> {
        match self.peek() {
            Some(token) if token.kind == SyntaxKind::Minus => {
                if nesting >= MAX_NESTING {
                    return Err(self.error("expression nesting limit exceeded"));
                }
                self.bump();
                let right = self.unary(nesting + 1)?;
                Ok(Expr::Unary {
                    op: UnaryOp::Negate,
                    right: Box::new(right),
                })
            }
            _ => self.primary(nesting),
        }
    }

    fn primary(&mut self, nesting: usize) -> Result<Expr, ParseError> {
        let token = match self.peek() {
            Some(token) => token,
            None => return Err(self.error("expected an expression")),
        };
        match token.kind {
            SyntaxKind::Number => self.number(),
            SyntaxKind::LeftParen => {
                if nesting >= MAX_NESTING {
                    return Err(self.error("expression nesting limit exceeded"));
                }
                self.bump();
                let inner = self.expression(nesting + 1)?;
                match self.peek() {
                    Some(close) if close.kind == SyntaxKind::RightParen => self.bump(),
                    _ => return Err(self.error("expected ')'")),
                }
                Ok(Expr::Grouping(Box::new(inner)))
            }
            _ => Err(self.error("expected an expression")),
        }
    }

    fn number(&mut self) -> Result<Expr, ParseError> {
        let token = match self.peek() {
            Some(token) => token,
            None => return Err(self.error("expected a number")),
        };
        if token.kind != SyntaxKind::Number {
            return Err(self.error("expected a number"));
        }

        let spelling = token
            .range
            .slice(self.source)
            .expect("scanner ranges are valid");
        let value = spelling
            .parse::<f64>()
            .map_err(|_| error_at(token, "invalid number"))?;
        self.bump();
        Ok(Expr::Number(value))
    }

    fn peek(&self) -> Option<Token> {
        self.tokens.get(self.current).copied()
    }

    fn bump(&mut self) {
        self.current += 1;
    }

    fn error(&self, message: &str) -> ParseError {
        match self.peek() {
            Some(token) => error_at(token, message),
            None => {
                let end = TextSize(self.source.len());
                ParseError {
                    message: message.to_owned(),
                    range: TextRange::new(end, end).expect("ordered EOF range"),
                }
            }
        }
    }
}
```
