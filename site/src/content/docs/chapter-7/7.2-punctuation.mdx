<p className="book-subtitle">Chapter 7 · From Handwritten Scanning to Logos</p>

We can scan `a!=b`, but `a<=b` still contains an `Error` for `<`, followed by
an `Equal` token. Our scanner recognizes only the punctuation we used to
learn its mechanics. We’ll now fill in Lox’s remaining punctuation and
comparison operators.

With Logos, each fixed spelling gets an attribute beside its kind. The
adapter we wrote in 7.1 already handles the resulting tokens and byte ranges.
We can extend the recognized vocabulary without adding cursor code.

Start from [Section 7.1](/chapter-7/7.1-logos/), with your terminal in
**`rlox/`**. All edits belong to **`rlox/crates/syntax/src/lib.rs`**. Keep
`Token`, `scan`, the regex rules, and existing tests in place.

## Add the remaining single-character spellings

We already recognize parentheses and `/`. Lox also uses braces, comma, dot,
minus, plus, semicolon, and star. Add these variants **inside `SyntaxKind`,
immediately before the existing `#[token("/")]` attribute**:

```rust title="rlox/crates/syntax/src/lib.rs · insert before Slash"
#[token("{")]
LeftBrace,
#[token("}")]
RightBrace,
#[token(",")]
Comma,
#[token(".")]
Dot,
#[token("-")]
Minus,
#[token("+")]
Plus,
#[token(";")]
Semicolon,
```

Keep `#[token("/")]` and `Slash,` unchanged. **Immediately after `Slash,`
and before `#[token("!")]`**, add:

```rust title="rlox/crates/syntax/src/lib.rs · insert after Slash"
#[token("*")]
Star,
```

Each attribute describes a literal spelling. `#[token(".")]` recognizes a
dot; `#[token("*")]` recognizes a star. The variants give those source pieces
distinct names for later consumers. They extend the enum’s alternatives in
the same way described by the Rust Book’s
[enum values discussion](https://doc.rust-lang.org/book/ch06-01-defining-an-enum.html#enum-values).

These names identify tokens; they don’t yet implement arithmetic, blocks,
or property access. Those behaviors will use the tokens when we build the
parser and execution layers.

## Add the comparison families

We have the `!`/`!=` and `=`/`==` pairs. Add the remaining comparison kinds
**immediately after `EqualEqual,` and before `Identifier`’s regex attribute**:

```rust title="rlox/crates/syntax/src/lib.rs · insert after EqualEqual"
#[token(">")]
Greater,
#[token(">=")]
GreaterEqual,
#[token("<")]
Less,
#[token("<=")]
LessEqual,
```

At a `<`, both `<` and `<=` can begin a match. When the equals sign follows,
Logos takes the longer fixed spelling. When it doesn’t, `<` remains a complete
token. The [disambiguation rules](https://logos.maciej.codes/token-disambiguation.html)
explain this preference; we don’t need a handwritten lookahead branch or an
explicit priority value for these fixed spellings.

A longer match still has an exact end. For `<==>==`, the first token consumes
two characters, then the next `=` begins its own token:

```text title="Longer operators leave the next character available"
source: "<==>=="

LessEqual     [0, 2)  "<="
Equal         [2, 3)  "="
GreaterEqual  [3, 5)  ">="
Equal         [5, 6)  "="
```

There is no `<==` or `>==` token. The next scan begins at the byte where the
previous match ended. Whitespace isn’t required to separate these spellings.

Every input here is one ASCII byte. Each must produce exactly one token of
the named kind, covering that byte. The existing tests continue to check

use logos::Logos;

use rlox_text::{TextRange, TextSize};

#[derive(Logos, Debug, Clone, Copy, PartialEq, Eq)]
pub enum SyntaxKind {
    #[token("(")]
    LeftParen,
    #[token(")")]
    RightParen,
    #[token("{")]
    LeftBrace,
    #[token("}")]
    RightBrace,
    #[token(",")]
    Comma,
    #[token(".")]
    Dot,
    #[token("-")]
    Minus,
    #[token("+")]
    Plus,
    #[token(";")]
    Semicolon,
    #[token("/")]
    Slash,
    #[token("*")]
    Star,
    #[token("!")]
    Bang,
    #[token("!=")]
    BangEqual,
    #[token("=")]
    Equal,
    #[token("==")]
    EqualEqual,
    #[token(">")]
    Greater,
    #[token(">=")]
    GreaterEqual,
    #[token("<")]
    Less,
    #[token("<=")]
    LessEqual,
    #[regex(r"[A-Za-z_][A-Za-z0-9_]*")]
    Identifier,
    #[regex(r"[ \t\r\n]+")]
    Whitespace,
    #[regex(r"//[^\n]*", allow_greedy = true)]
    LineComment,
    Error,
}

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub struct Token {
    pub kind: SyntaxKind,
    pub range: TextRange,
}

pub fn scan(source: &str) -> Vec<Token> {
    let mut tokens = Vec::new();

    for (result, span) in SyntaxKind::lexer(source).spanned() {
        let kind = match result {
            Ok(kind) => kind,
            Err(()) => SyntaxKind::Error,
        };
        let range = TextRange::new(TextSize(span.start), TextSize(span.end))
            .expect("Logos spans are ordered");

        tokens.push(Token { kind, range });
    }

    tokens
}

                offset = end;

            assert_eq!(reconstructed, source);

All of Lox’s punctuation now has a token kind. The next distinction is
between an ordinary name and a reserved word with the same identifier-shaped
spelling.

The [token kinds in Crafting Interpreters](https://craftinginterpreters.com/scanning.html#token-type)
provide the vocabulary we’re following; our retained trivia and source ranges
keep the additional information that later syntax and editor tools need.
