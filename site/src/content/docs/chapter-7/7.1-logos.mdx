<p className="book-subtitle">Chapter 7 · From Handwritten Scanning to Logos</p>

Our scanner can recognize `a_2!=other`. Its rules also manage a cursor:
consume the first character, inspect the next, advance when it belongs to the
token, and update the end offset. Identifiers, whitespace, and comments each
contain a version of that growing loop.

We can describe their spellings more directly. For example, an identifier is
an ASCII letter or underscore followed by zero or more ASCII letters,
digits, or underscores. **Logos** turns descriptions like that into scanning
code at compile time. We’ll replace the mechanics while keeping the results:
`Identifier [0, 3)`, `BangEqual [3, 5)`, and `Identifier [5, 10)`.

Start from [Section 6.3](/chapter-6/6.3-line-comments/), with your terminal in
**`rlox/`**. This section changes **`crates/syntax/Cargo.toml`** and
**`crates/syntax/src/lib.rs`**. We’ll keep the same `SyntaxKind`, `Token`, and
`scan(source: &str) -> Vec<Token>` boundary.

## Check the behavior before replacing it

Our existing tests describe more than successful recognition. They check
trivia, UTF-8 boundaries, and exact source reconstruction. Keep those tests
and their expected results unchanged during this migration.

One additional case makes our error boundary explicit. The handwritten
scanner emits one `Error` token per unsupported character. A replacement
that groups adjacent unknown characters could still reconstruct the source,
but it would change the token stream.

Before adding Logos, append this test **inside the existing `mod tests` in
`rlox/crates/syntax/src/lib.rs`, before its closing brace**. Keep the existing
imports and tests:

## Put fixed spellings beside their kinds

At the top of **`rlox/crates/syntax/src/lib.rs`**, import `Logos` before our
text types:

```diff title="rlox/crates/syntax/src/lib.rs · imports"
+use logos::Logos;
+
 use rlox_text::{TextRange, TextSize};
```

Add `Logos` to the derive **on `SyntaxKind`**. Leave `Token`’s derive alone:

```diff title="rlox/crates/syntax/src/lib.rs · SyntaxKind derive"
-#[derive(Debug, Clone, Copy, PartialEq, Eq)]
+#[derive(Logos, Debug, Clone, Copy, PartialEq, Eq)]
 pub enum SyntaxKind {
```

We’ve used derives to obtain comparisons and debug formatting. This one
generates a lexer implementation. Its helper attributes describe the input
patterns for each kind. The Rust Book introduces
[procedural derive macros](https://doc.rust-lang.org/book/ch20-05-macros.html#procedural-macros-for-generating-code-from-attributes).
We’re using a derive, rather than writing a macro ourselves.

Inside `SyntaxKind`, add `#[token(...)]` to the seven fixed-spelling variants,
keeping their names and order:

```rust title="rlox/crates/syntax/src/lib.rs · fixed-spelling variants"
#[token("(")]
LeftParen,
#[token(")")]
RightParen,
#[token("/")]
Slash,
#[token("!")]
Bang,
#[token("!=")]
BangEqual,
#[token("=")]
Equal,
#[token("==")]
EqualEqual,
```

These are literal spellings, so `(` doesn’t need to be escaped as a regular
expression. The [token and regex attributes](https://logos.maciej.codes/attributes/token_and_regex.html)
attach patterns to existing enum variants; there’s no second kind enum or
conversion list to maintain.

Logos can distinguish a fixed spelling from its longer match. `!=` becomes
`BangEqual`, and `//` can start a comment rather than two slash tokens. Our
existing tests already check these boundaries. The handbook’s
[disambiguation discussion](https://logos.maciej.codes/token-disambiguation.html)
explains how length and pattern specificity guide that choice.

## Describe the growing tokens

A **regular expression** describes a family of spellings. We need only
character classes and repetition to express the rules we already wrote.

Annotate `Identifier` like this:

```rust title="rlox/crates/syntax/src/lib.rs · identifier rule"
#[regex(r"[A-Za-z_][A-Za-z0-9_]*")]
Identifier,
```

`[A-Za-z_]` matches one ASCII letter or underscore. `[A-Za-z0-9_]` adds digits
to that set, and `*` means zero or more repetitions. The first character is
required; the continuation may be empty. This is the same start/continuation
distinction as 6.1, not a new naming rule.

The `r"..."` syntax is a Rust **raw string**: Rust passes backslashes through
rather than interpreting them first. That matters in our next two patterns.
Add this attribute to `Whitespace`:

```rust title="rlox/crates/syntax/src/lib.rs · whitespace rule"
#[regex(r"[ \t\r\n]+")]
Whitespace,
```

The regex engine interprets `\t`, `\r`, and `\n` as tab, carriage return, and
line feed. `+` means one or more characters from the class, so it groups a
whole run and cannot produce an empty token. The set remains exactly the
four whitespace characters from 6.2.

Finally, annotate `LineComment`:

```rust title="rlox/crates/syntax/src/lib.rs · comment rule"
#[regex(r"//[^\n]*", allow_greedy = true)]
LineComment,
```

The literal `//` is followed by zero or more characters other than line feed.
Inside `[^\n]`, the leading `^` negates the class. An empty comment body is
allowed, CR stays in the body, and LF remains for the whitespace rule. A
comment can also reach EOF.

Logos requires an explicit opt-in for this unbounded greedy character class.
`allow_greedy = true` permits it: our rule deliberately consumes the whole
comment body up to LF or EOF, and the class still excludes LF. The handbook
explains this check under
[greedy repetition](https://logos.maciej.codes/common-regex.html#common-performance-pitfalls).

Keep the existing **`Error,`** variant after these rules, with **no pattern
attribute**. We’ll select it when Logos reports an unmatched input. The enum
still has exactly the same kinds as before.

Whitespace and comments are ordinary returned kinds. We aren’t using skip
attributes: losing trivia would violate our source-reconstruction contract.

## Turn lexer results into our tokens

Logos supplies the recognition and byte spans. Our `scan` function still
needs to produce the project’s `Token` values and use `TextRange`.

**Replace the entire existing `scan` function**, from its `pub fn scan` line
through that function’s closing brace, with this version. Keep the `Token`
definition above it and the test module below it unchanged:

```rust title="rlox/crates/syntax/src/lib.rs · replace scan"
pub fn scan(source: &str) -> Vec<Token> {
    let mut tokens = Vec::new();

    for (result, span) in SyntaxKind::lexer(source).spanned() {
        let kind = match result {
            Ok(kind) => kind,
            Err(()) => SyntaxKind::Error,
        };
        let range = TextRange::new(TextSize(span.start), TextSize(span.end))
            .expect("Logos spans are ordered");

        tokens.push(Token { kind, range });
    }

    tokens
}
```

The import brings the `Logos` trait into scope, allowing
`SyntaxKind::lexer(source)` to construct its lexer. The same import also
makes the derive macro available.

Calling [`spanned()`](https://docs.rs/logos/0.16.1/logos/struct.Lexer.html#method.spanned)
gives an iterator of result/span pairs. Its item type is
`(Result<SyntaxKind, ()>, Range<usize>)`: each successful result contains a
kind, and each span has public `start` and `end` byte offsets. We wrap those
offsets in the same coordinate types we already use. The constructor’s
`expect` states the span-order invariant supplied by the lexer.

An unmatched input returns `Err(())`. The empty tuple `()` carries no error
payload; the accompanying span still tells us where the input occurred.
We convert that result into our existing `SyntaxKind::Error`. It remains a
token in the returned vector, so reconstruction includes those source bytes.
We don’t add a second error representation or print a diagnostic here.

For the CRLF example from 6.3, the adapter should preserve this mapping:

```text title="Logos results and spans become the existing tokens"
source: "//é\r\nname"

Ok(LineComment), 0..5  -> LineComment [0, 5)
Ok(Whitespace),  5..6  -> Whitespace  [5, 6)
Ok(Identifier),  6..10 -> Identifier  [6, 10)
```

The existing exact-range test checks that mapping, including LF staying
outside the comment. The adjacent-unknown-character test checks that error
spans still select complete individual characters. The partition test checks
that successful and error tokens together retain all the source.

Replacing `scan` removes its handwritten matching and cursor loops. The
complete earlier implementation remains in Section 6.3 for reference; we
won’t carry an unused second scanner into the next lessons.

use logos::Logos;

use rlox_text::{TextRange, TextSize};

#[derive(Logos, Debug, Clone, Copy, PartialEq, Eq)]
pub enum SyntaxKind {
    #[token("(")]
    LeftParen,
    #[token(")")]
    RightParen,
    #[token("/")]
    Slash,
    #[token("!")]
    Bang,
    #[token("!=")]
    BangEqual,
    #[token("=")]
    Equal,
    #[token("==")]
    EqualEqual,
    #[regex(r"[A-Za-z_][A-Za-z0-9_]*")]
    Identifier,
    #[regex(r"[ \t\r\n]+")]
    Whitespace,
    #[regex(r"//[^\n]*", allow_greedy = true)]
    LineComment,
    Error,
}

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub struct Token {
    pub kind: SyntaxKind,
    pub range: TextRange,
}

pub fn scan(source: &str) -> Vec<Token> {
    let mut tokens = Vec::new();

    for (result, span) in SyntaxKind::lexer(source).spanned() {
        let kind = match result {
            Ok(kind) => kind,
            Err(()) => SyntaxKind::Error,
        };
        let range = TextRange::new(TextSize(span.start), TextSize(span.end))
            .expect("Logos spans are ordered");

        tokens.push(Token { kind, range });
    }

    tokens
}
