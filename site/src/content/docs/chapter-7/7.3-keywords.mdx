Our scanner currently gives `print` and `printer` the same kind:
`Identifier`. They both fit the character rules for a name, but Lox reserves
`print` for the language itself. We need its own kind while keeping `printer`
as an ordinary identifier.

Start from [Section 7.2](/chapter-7/7.2-punctuation/), with your terminal in
**`rlox/`**. All edits belong to **`rlox/crates/syntax/src/lib.rs`**. We’ll
add keyword patterns to the existing enum and keep its identifier rule.

## A kind and a spelling are different information

A token’s kind describes its category. Its range describes where the source
spells it. For the source `print printer`, our target stream is:

```text title="Kinds, locations, and original spellings"
Print       [0, 5)   "print"
Whitespace  [5, 6)   " "
Identifier  [6, 13)  "printer"
```

Where is the identifier’s actual text? It’s still in the original source.
Given that source and the last token, `token.range.slice(source)` returns
`Some("printer")`. The same method retrieves `"print"` from the keyword token
and the space from the whitespace token.

`Token` doesn’t need a separate string field for each piece. The caller keeps
the source, and the range lets us borrow the original characters when needed.
Use the source the tokens were scanned from: offsets alone don’t remember
which string they describe.

The returned `&str` is a **borrowed slice**, usable while its source remains
available. The Rust Book’s
[string slices discussion](https://doc.rust-lang.org/book/ch04-03-slices.html#string-slices)
explains that relationship. Our `TextRange::slice` also checks the bounds and
UTF-8 boundaries, which is why it returns `Option<&str>`.

An identifier’s kind can therefore stay the simple `Identifier` variant while
its spelling varies. Later consumers can ask for that spelling through the
range. We’ll check this explicitly after adding the keyword rules.

## Give reserved words their own kinds

The new kinds make the reserved words available to later grammar rules.

## Let the whole word decide

Both `#[token("for")]` and the identifier regex can match the complete input
`for`. Logos prefers the specific fixed spelling, giving us `For`.

For `forest`, however, the identifier rule matches the longer word. The
result is one `Identifier`, rather than `For` followed by another token.
Similarly, `printer` and `true_value` remain whole names. Logos’s
[disambiguation rules](https://logos.maciej.codes/token-disambiguation.html)
cover these length and specificity choices; no separate keyword lookup or
manual priority value is needed here.

Matching is case-sensitive. `Print` remains an identifier because it differs
from the lowercase keyword. `_if` is also an identifier: containing keyword
letters doesn’t make the entire spelling a reserved word.

## Retrieve the text through the range

Add this test **inside the same module** for the opening example:

```rust title="rlox/crates/syntax/src/lib.rs · append inside mod tests"
#[test]
fn token_spelling_comes_from_the_source() {
    let source = "print printer";
    let tokens = scan(source);

    assert_eq!(
        tokens,
        vec![
            Token {
                kind: SyntaxKind::Print,
                range: TextRange::new(TextSize(0), TextSize(5)).unwrap(),
            },
            Token {
                kind: SyntaxKind::Whitespace,
                range: TextRange::new(TextSize(5), TextSize(6)).unwrap(),
            },
            Token {
                kind: SyntaxKind::Identifier,
                range: TextRange::new(TextSize(6), TextSize(13)).unwrap(),
            },
        ]
    );
    assert_eq!(tokens[0].range.slice(source), Some("print"));
    assert_eq!(tokens[1].range.slice(source), Some(" "));
    assert_eq!(tokens[2].range.slice(source), Some("printer"));
}
```

The first assertion checks category and location. The remaining assertions
borrow the exact source pieces through those locations. They demonstrate
that recognizing a keyword doesn’t discard its spelling, and that an
identifier’s variable text is available without a payload in `SyntaxKind`.
The source is borrowed throughout; scanning and slicing leave it intact.

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub struct Token {
    pub kind: SyntaxKind,
    pub range: TextRange,
}

pub fn scan(source: &str) -> Vec<Token> {
    let mut tokens = Vec::new();

    for (result, span) in SyntaxKind::lexer(source).spanned() {
        let kind = match result {
            Ok(kind) => kind,
            Err(()) => SyntaxKind::Error,
        };
        let range = TextRange::new(TextSize(span.start), TextSize(span.end))
            .expect("Logos spans are ordered");

        tokens.push(Token { kind, range });
    }

    tokens
}

The scanner now distinguishes reserved words from ordinary names while
keeping their source text available through the same ranges. Next we’ll
recognize number spellings, which need a different continuation rule.

[Crafting Interpreters, “Reserved Words and Identifiers”](https://craftinginterpreters.com/scanning.html#reserved-words-and-identifiers)
introduces the same vocabulary. Our Logos rules make the fixed spellings
part of the kind definition, and our ranges retain the original text.
