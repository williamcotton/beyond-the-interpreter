In `print "hello";`, the word `hello` currently becomes an identifier and each
quote becomes an error. But those quotes change what the characters between
them mean. Spaces, digits and even `//` inside a string belong to that string,
rather than becoming separate tokens.

Start from [Section 7.4](/chapter-7/7.4-numbers/), with your terminal in
**`rlox/`**. All edits belong to **`rlox/crates/syntax/src/lib.rs`**.

## From opening quote to closing quote

A Lox string starts with `"` and ends at the next `"`. It can be empty, and
its contents can include Unicode characters and actual line breaks. These
are the [string rules in Crafting Interpreters](https://craftinginterpreters.com/scanning.html#string-literals).

Our token range will include both quotes. For the source `print "é";`, the
target is:

```text title="The string keeps its delimiters and original bytes"
Print       [0, 5)   "print"
Whitespace  [5, 6)   " "
String      [6, 10)  "\"é\""
Semicolon   [10, 11) ";"
```

The string occupies four bytes: one opening quote, two bytes for `é`, and one
closing quote. As with numbers and names, `token.range.slice(source)` returns
the original spelling. Later code can derive a string's value from that
spelling; the scanner keeps the source intact.

## Match everything except another quote

Inside `SyntaxKind`, insert these lines **immediately before the existing
`#[regex(r"[0-9]+(\.[0-9]+)?")]` attribute on `Number`**:

```rust title="rlox/crates/syntax/src/lib.rs · insert before Number"
#[regex(r#""[^"]*""#)]
String,
```

The regex itself is `"[^"]*"`: an opening quote, zero or more characters
other than a quote, then a closing quote. Because the repeated class excludes
`"`, it cannot swallow the closing delimiter or merge adjacent strings.
Unlike a dot wildcard, this class also accepts line breaks without a flag.
It accepts spaces, slashes and other punctuation too; they stay inside the
single `String` token.

The Rust notation needs a closer look. Our earlier `r"..."` raw strings
couldn't contain a quote because that quote would end the Rust
literal. Here `r#"..."#` uses matching hashes around its delimiters, allowing
ordinary quote characters inside. Only the ending `"#` closes this Rust raw
string. The [Rust Reference's raw string discussion](https://doc.rust-lang.org/reference/tokens.html#raw-string-literals)
describes that syntax. The hashes are Rust notation, not part of the regex
or the Lox source being matched.

`String` here is an enum variant, `SyntaxKind::String`. It has no owned string
field, and it doesn't change the standard library's `String` type used in our
reconstruction test. Keep `Token`, `scan`, the other rules, imports, and
manifest unchanged.

## Backslashes remain ordinary characters

Lox doesn't process escape sequences. Inside a Lox string, the two characters
`\` and `n` remain two characters; they aren't converted into a line break.
An actual line break is also allowed. A backslash doesn't protect a following
quote: that quote still ends the string.

This is distinct from how we write test inputs in Rust. Rust's `"\n"`
constructs an actual line break, while `r"\n"` constructs a backslash and `n`.
We'll use Rust raw strings when the exact Lox quote/backslash spelling needs
to stay visible, and ordinary Rust strings when inserting an actual newline.

Append these tests **inside the existing `mod tests`, before its closing
brace**, retaining the existing imports and tests:

```rust title="rlox/crates/syntax/src/lib.rs · append inside mod tests"
#[test]
fn keeps_complete_string_spellings() {
    for source in [
        r#""""#,
        r#""hello""#,
        r#""// 123 ; print""#,
        "\"é💥\"",
        "\"first\nsecond\"",
        r#""\n""#,
    ] {
        let tokens = scan(source);
        assert_eq!(
            tokens,
            vec![Token {
                kind: SyntaxKind::String,
                range: TextRange::new(TextSize(0), TextSize(source.len())).unwrap(),
            }]
        );
        assert_eq!(tokens[0].range.slice(source), Some(source));
    }
}

#[test]
fn strings_stop_at_the_next_quote() {
    let source = r#""a""b";"#;
    let tokens = scan(source);
    assert_eq!(
        tokens,
        vec![
            Token {
                kind: SyntaxKind::String,
                range: TextRange::new(TextSize(0), TextSize(3)).unwrap(),

                kind: SyntaxKind::String,
                range: TextRange::new(TextSize(3), TextSize(6)).unwrap(),
            },

                kind: SyntaxKind::Semicolon,
                range: TextRange::new(TextSize(6), TextSize(7)).unwrap(),
            },

    assert_eq!(tokens[0].range.slice(source), Some(r#""a""#));
    assert_eq!(tokens[1].range.slice(source), Some(r#""b""#));
}

#[test]

    let source = r#""\"name"#;
    assert_eq!(
        scan(source),
        vec![
            Token {
                kind: SyntaxKind::String,
                range: TextRange::new(TextSize(0), TextSize(3)).unwrap(),

                kind: SyntaxKind::Identifier,

            },
        ]
    );
}
```

The first test checks complete spellings, including empty, UTF-8, multiline
and literal backslash contents. The next test requires adjacent quoted pieces
to stay separate and leaves the semicolon outside. The last input contains an
opening quote, a backslash, a closing quote and `name`: its string ends after
three bytes, and the name becomes an identifier.

## If the closing quote never arrives

For the source consisting of an opening quote followed by `é`, we want one
error covering all three bytes:

```text title="An unfinished string remains one source fragment"
Error  [0, 3)  "\"é"
```

The closing quote is required by the rule, so this isn't a successful string
match. Logos can read the opening quote and all the non-quote contents, but
reaches the end without completing a token. Its
[error span rules](https://logos.maciej.codes/common-regex.html#error-semantics)
let our existing adapter retain that consumed fragment as `Error`.
No callback or second scanning loop is needed.

This expands the reason for an error range: an unknown character still
produces its own error, while an unfinished string spans from its opening
quote through EOF. There is no newline recovery here because Lox permits
multiline strings. Text that looks like a comment remains part of the
unfinished string too. A later diagnostic can explain the missing delimiter;
for now we preserve the text and finish scanning without losing bytes or
repeating the same position.

Append this test **inside the same test module**:

```rust title="rlox/crates/syntax/src/lib.rs · append inside mod tests"
#[test]
fn unterminated_strings_cover_the_remaining_source() {
    for source in ["\"", "\"é", "\"first\n// still inside"] {
        let tokens = scan(source);
        assert_eq!(
            tokens,
            vec![Token {
                kind: SyntaxKind::Error,
                range: TextRange::new(TextSize(0), TextSize(source.len())).unwrap(),
            }]
        );
        assert_eq!(tokens[0].range.slice(source), Some(source));
    }

    assert_eq!(
        scan(r#""ok""é"#),
        vec![
            Token {
                kind: SyntaxKind::String,
                range: TextRange::new(TextSize(0), TextSize(4)).unwrap(),
            },
            Token {
                kind: SyntaxKind::Error,
                range: TextRange::new(TextSize(4), TextSize(7)).unwrap(),
            },
        ]
    );
}
```

The first cases cover a lone opening quote, a multibyte character and an
actual newline followed by comment-like text. The final case checks that a
complete string can be followed immediately by an unfinished one: only the
second fragment becomes `Error`, at its own byte offset.

## Preserve the whole source

Extend the input array in `token_ranges_cover_the_original_source` by adding
these entries **after `"print 0.5;//é\n123.",`**, leaving all prior inputs
and its checking loop intact:

```rust title="rlox/crates/syntax/src/lib.rs · append coverage inputs"
r#"print "é";"#,
r#""a""b";"#,
r#""\"name"#,
"\"first\nsecond\" // done\n0.5",
"\"",
"\"é",
"\"first\n// still inside",
r#""ok""é"#,
```

These cases put successful and unfinished strings into the existing
contiguous-range and exact-reconstruction checks. Retained trivia still
covers whitespace and comments outside a string; characters inside one
belong to its range.

From **`rlox/`**, run:

```sh
cargo test -p rlox-syntax
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
```

The tests should pass for complete, multiline and unfinished strings. In
the unfinished case, check both the Error kind and its extent through EOF.
That extent is what lets a later tool identify the whole attempted string.

We now have rules for Lox's lexical categories, including strings. Our scanner
also keeps whitespace, comments and malformed fragments, giving later tools
the original source as well as its token kinds. The command-line program
still displays source; making tokens inspectable is the next chapter's job.

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub struct Token {
    pub kind: SyntaxKind,
    pub range: TextRange,
}

pub fn scan(source: &str) -> Vec<Token> {
    let mut tokens = Vec::new();

    for (result, span) in SyntaxKind::lexer(source).spanned() {
        let kind = match result {
            Ok(kind) => kind,
            Err(()) => SyntaxKind::Error,
        };
        let range = TextRange::new(TextSize(span.start), TextSize(span.end))
            .expect("Logos spans are ordered");

        tokens.push(Token { kind, range });
    }

    tokens
}
