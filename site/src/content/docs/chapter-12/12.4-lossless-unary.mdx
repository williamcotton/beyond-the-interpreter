Our concrete parser recognizes `(12.5)`, but `-12.5` still starts with an
unexpected token. The scanner already keeps the minus separate from the
number. Now the parser needs to connect that operator to its operand.

The owned parser taught us this shape in [11.3](/chapter-11/11.3-parse-unary/).
This time we'll also keep the actual operator token and the text between
it and its operand. For `- // é\n12.5`, where `\n` represents a newline,
we want:

```text title="Unary structure preserves the source between operator and operand"
Root [0..12)
  UnaryExpr [0..12)
    Minus [0..1) "-"
    Whitespace [1..2) " "
    LineComment [2..7) "// é"
    Whitespace [7..8) "\n"
    NumberExpr [8..12)
      Number [8..12) "12.5"
```

The comment doesn't become part of the number token. It remains a sibling
of the operand node inside `UnaryExpr`. The minus is also a token child,
so a later view can read its kind, spelling and location from the source.

Start from [12.3](/chapter-12/12.3-lossless-groups/), in the **Rust workspace
directory**. We'll add negation to the concrete parser while keeping the
owned arithmetic parser and both previous inspection examples intact.

## Put unary between expression and primary

We can use the same recursive-descent grammar as the owned parser:

```text
expression → unary
unary      → "-" unary | primary
primary    → NUMBER | "(" expression ")"
```

A unary operand can itself begin with minus, which gives `--1` nested
unary nodes. Otherwise we fall through to a number or group. A group still
calls `expression` for its contents, so `-(1)` and `(-1)` both fit the
rules. This is our negation-only subset of the
[unary rule in Crafting Interpreters](https://craftinginterpreters.com/parsing-expressions.html#recursive-descent-parsing).

Insert these two methods **immediately before `primary`**:

```rust title="rlox/crates/syntax/src/cst.rs · insert expression and unary"
    fn expression(&mut self, nesting: usize) -> Result<(), ParseError> {
        self.unary(nesting)
    }

    fn unary(&mut self, nesting: usize) -> Result<(), ParseError> {
        self.eat_trivia();
        match self.peek() {
            Some(token) if token.kind == SyntaxKind::Minus => {
                if nesting >= MAX_NESTING {
                    return Err(self.error("expression nesting limit exceeded"));
                }
                self.builder.start_node(SyntaxKind::UnaryExpr.into_raw());
                self.bump();
                let result = self.unary(nesting + 1);
                self.builder.finish_node();
                result
            }
            _ => self.primary(nesting),
        }
    }
```

On a minus, `unary` first checks the shared resource budget. It then opens
`UnaryExpr`, emits the operator with `bump`, and calls itself for the
operand. Another minus opens a nested unary node. A number or opening
parenthesis delegates to `primary` at the same depth.

We save the operand's `Result`, close the unary node, and return that
result. This is the same balancing rule used by `group`: a failing child
mustn't skip `finish_node`. An early `?` here would return before closing
the node; see the Rust Book's
[error-propagation explanation](https://doc.rust-lang.org/book/ch09-02-recoverable-errors-with-result.html#propagating-errors).

The existing `group` method needs no edit. Its call to `expression` now
reaches the new unary rule. Both a group wrapper and a unary wrapper add
one to the same `nesting` count; numbers add none. A path with 63 minuses
and one group reaches the limit of 64, just like 64 groups or 64 minuses.
A separate unary counter would allow mixed paths to exceed that limit.

## Keep trivia at the container that consumes it

`unary` calls `eat_trivia` before choosing an expression. On the first call,
that emits leading trivia into `Root`. After consuming a minus, the
recursive call emits intervening trivia into the open `UnaryExpr`. Only
then does it open the operand node.

Once the operand finishes, the unary node closes. Later trivia is consumed
by the enclosing group or root as before. For ` -1 `, the root therefore
has a space token, a unary node with text `-1`, and another space token.
For `- // é\n12.5`, the comment and newline fall *between* operator and
operand, so they stay inside the unary node shown above.

The scanner's `Error` token still isn't trivia. For `-é`, the operator is
consumed but the operand fails at `[1..3)`. The unary node closes with just
the minus; 12.3's final drain retains `é` in the root. All source survives,
even though no operand node was created.

An absent operand inside a group follows the same path. For `(-)`:

```text title="A failed operand still leaves balanced partial nodes"
Root [0..3)
  GroupingExpr [0..2)
    LeftParen [0..1) "("
    UnaryExpr [1..2)
      Minus [1..2) "-"
  RightParen [2..3) ")"
error: expected an expression [2..3)
```

The surviving `)` is in the root because our current policy stops at the
first error and drains the suffix there. We haven't added a missing token
or resumed the group rule after the failed operand. More local recovery
comes after the arithmetic grammar is migrated.

a single byte in these cases, so the rejected opening appears at byte 64.
Its suffix is still retained after the partial nodes close.

pub fn scan(source: &str) -> Result<Vec<Token>, SourceTooLarge> {
    checked_size(source.len())?;
    let mut tokens = Vec::new();

    for (result, span) in SyntaxKind::lexer(source).spanned() {
        let kind = match result {
            Ok(kind) => kind,
            Err(()) => SyntaxKind::Error,
        };
        let range = checked_range(
            checked_size(span.start).expect("validated source length"),
            checked_size(span.end).expect("validated source length"),
        )
        .expect("Logos spans are ordered");

        tokens.push(Token { kind, range });
    }

    Ok(tokens)

pub struct Parse {
    pub root: SyntaxNode,
    pub errors: Vec<ParseError>,

pub fn parse(source: &str) -> Result<Parse, SourceTooLarge> {
    let mut parser = Parser::new(source)?;
    parser.builder.start_node(SyntaxKind::Root.into_raw());
    let mut errors = Vec::new();
    match parser.expression(0) {
        Err(error) => errors.push(error),
        Ok(()) => {
            parser.eat_trivia();
            if parser.peek().is_some() {
                errors.push(parser.error("expected end of input"));
            }
        }
    }

    while parser.current < parser.tokens.len() {
        parser.bump();
    }
    parser.builder.finish_node();
    let root = SyntaxNode::new_root(parser.builder.finish());
    Ok(Parse { root, errors })
}

struct Parser<'src> {
    source: &'src str,
    tokens: Vec<Token>,
    current: usize,
    builder: GreenNodeBuilder<'static>,
}

impl<'src> Parser<'src> {
    fn new(source: &'src str) -> Result<Self, SourceTooLarge> {
        Ok(Self {
            source,
            tokens: scan(source)?,
            current: 0,
            builder: GreenNodeBuilder::new(),
        })
    }

    fn peek(&self) -> Option<Token> {
        self.tokens.get(self.current).copied()
    }

    fn bump(&mut self) {
        let token = self.tokens[self.current];
        let spelling = slice(self.source, token.range).expect("scanner ranges are valid");
        self.builder.token(token.kind.into_raw(), spelling);
        self.current += 1;
    }

    fn eat_trivia(&mut self) {
        while let Some(token) = self.peek() {
            if !matches!(token.kind, SyntaxKind::Whitespace | SyntaxKind::LineComment) {
                break;
            }
            self.bump();
        }
    }

    fn error(&self, message: &str) -> ParseError {
        match self.peek() {
            Some(token) => ParseError {
                message: if token.kind == SyntaxKind::Error {
                    "invalid token".to_owned()
                } else {
                    message.to_owned()
                },
                range: token.range,
            },
            None => {
                let end = checked_size(self.source.len()).expect("validated source length");
                ParseError {
                    message: message.to_owned(),
                    range: checked_range(end, end).expect("ordered EOF range"),
                }
            }
        }
    }

    fn expression(&mut self, nesting: usize) -> Result<(), ParseError> {
        self.unary(nesting)
    }

    fn unary(&mut self, nesting: usize) -> Result<(), ParseError> {
        self.eat_trivia();
        match self.peek() {
            Some(token) if token.kind == SyntaxKind::Minus => {
                if nesting >= MAX_NESTING {
                    return Err(self.error("expression nesting limit exceeded"));
                }
                self.builder.start_node(SyntaxKind::UnaryExpr.into_raw());
                self.bump();
                let result = self.unary(nesting + 1);
                self.builder.finish_node();
                result
            }
            _ => self.primary(nesting),
        }
    }

    fn primary(&mut self, nesting: usize) -> Result<(), ParseError> {
        match self.peek() {
            Some(token) if token.kind == SyntaxKind::Number => {
                self.builder.start_node(SyntaxKind::NumberExpr.into_raw());
                self.bump();
                self.builder.finish_node();
                Ok(())
            }
            Some(token) if token.kind == SyntaxKind::LeftParen => self.group(nesting),
            _ => Err(self.error("expected an expression")),
        }
    }

    fn group(&mut self, nesting: usize) -> Result<(), ParseError> {
        if nesting >= MAX_NESTING {
            return Err(self.error("expression nesting limit exceeded"));
        }
        self.builder.start_node(SyntaxKind::GroupingExpr.into_raw());
        self.bump();
        let result = match self.expression(nesting + 1) {
            Err(error) => Err(error),
            Ok(()) => {
                self.eat_trivia();
                match self.peek() {
                    Some(token) if token.kind == SyntaxKind::RightParen => {
                        self.bump();
                        Ok(())
                    }
                    _ => Err(self.error("expected ')'")),
                }
            }
        };
        self.builder.finish_node();
        result
    }
