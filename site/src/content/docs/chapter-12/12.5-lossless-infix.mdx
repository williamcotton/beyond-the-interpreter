Our concrete parser can finish the `1` in `1 + 2 * 3`, but it then reports
an unexpected `+`. For a binary expression, the left operand is already
in the builder when we discover that it needs a parent. How do we put a
node around something we've already emitted?

Rowan gives us a **checkpoint**: a saved position among the current
container's children. After emitting operands and their operator, we can
wrap everything from that position in a `BinaryExpr`.

The grammar still chooses which operands belong together. Explore these
fixed sources: compare multiplication inside addition, explicit grouping,
and a subtraction chain. The owned tree captures the operation; the
concrete tree also retains the tokens that spell it.

<LosslessTree variant="arithmetic" client:load />

In `1 + 2 * 3`, the right child of the outer binary node is another binary
node for `2 * 3`. In `8 - 3 - 1`, it is the *left* child that is binary,
covering `8 - 3`. Repeated wrapping at the same checkpoint will give us
that left association.

Start from [12.4](/chapter-12/12.4-lossless-unary/), in the **Rust workspace
directory**. We'll add multiplication/division first, then addition and
subtraction, following the [precedence rules from Crafting Interpreters](https://craftinginterpreters.com/parsing-expressions.html#recursive-descent-parsing).

The owned parser returned a tree, so its caller could inspect that tree's
height. The builder now holds the completed structure. Each grammar call
can instead return just the height its caller needs. A number returns zero.
A group adds one to its child's height. A binary wrapper adds one to the
larger child height. Those small return values let the grammar enforce its
budget while Rowan accumulates the actual tree.

## Return height without keeping another AST

We already count group and unary wrappers against a limit of 64. A long
binary chain can also build a tall tree even though its parser uses a
loop. We need the same combined limit taught in Chapter 11.

Our grammar methods currently return `()` on success. Instead, each will
return the height of the expression it just emitted:

```text title="Height counts non-leaf expression nodes on the deepest path"
number           0
group or unary   1 + child height
binary           1 + max(left height, right height)

ancestor nesting + resulting height must be at most 64
```

This is one `usize` per result, not another expression tree. Unary and
group calls still increment ancestor `nesting` before recursing. Binary
loops compute their returned subtree height from the two operand heights.

## Look past trivia without emitting it

Before choosing an infix operator we must look through trivia. Consuming
that trivia too early would move trailing spaces into an expression that
has already finished. For example, the final space in `1 + 2 ` belongs
to the root, just as it did for `-1 `.

Insert this method **after `peek` and before `bump`** in **`cst.rs`**:

```rust title="rlox/crates/syntax/src/cst.rs · non-emitting operator lookahead"
    fn peek_non_trivia(&self) -> Option<Token> {
        self.tokens[self.current..]
            .iter()
            .copied()
            .find(|token| !matches!(token.kind, SyntaxKind::Whitespace | SyntaxKind::LineComment))
    }
```

This iterator inspects tokens from the current cursor and returns the
first non-trivia token. It does not advance `current` or write to the
builder. Only after a rule recognizes its operator will it call
`eat_trivia`, emitting those intervening tokens at their actual location.
The Rust Book describes [iterator adapters](https://doc.rust-lang.org/book/ch13-02-iterators.html#methods-that-produce-other-iterators)
used for this kind of traversal.

Add the one node kind after `UnaryExpr` in
**`rlox/crates/syntax/src/lib.rs`**:

```diff title="rlox/crates/syntax/src/lib.rs · binary kind"
     UnaryExpr,
+    BinaryExpr,

```

A checkpoint is a bookmark between a container's children, not a saved
parser cursor. Record it before emitting the left operand. Once the right
operand succeeds, `start_node_at` opens a node around the children emitted
since that bookmark; `finish_node` completes the wrapper. No source is read
again. Reusing the bookmark wraps the previous binary node into the next
left-associated parent.

## Wrap multiplication and division

Insert `factor` **between `expression` and `unary`** in **`cst.rs`**:

```rust title="rlox/crates/syntax/src/cst.rs · insert factor"
    fn factor(&mut self, nesting: usize) -> Result<usize, ParseError> {
        self.eat_trivia();
        let checkpoint = self.builder.checkpoint();
        let mut height = self.unary(nesting)?;

        while let Some(operator) = self.peek_non_trivia() {
            if !matches!(operator.kind, SyntaxKind::Star | SyntaxKind::Slash) {
                break;
            }
            self.eat_trivia();
            self.bump();
            let right_height = self.unary(nesting)?;
            let next_height = 1 + height.max(right_height);
            if nesting + next_height > MAX_NESTING {
                return Err(ParseError {
                    message: "expression nesting limit exceeded".to_owned(),
                    range: operator.range,
                });
            }
            self.builder
                .start_node_at(checkpoint, SyntaxKind::BinaryExpr.into_raw());
            self.builder.finish_node();
            height = next_height;
        }

        Ok(height)
    }
```

First we emit leading trivia into the current container, *then* save the
checkpoint. Otherwise a later wrapper would capture that leading trivia.
The first unary operand is built normally. If lookahead finds `*` or `/`,
we emit the intervening trivia and operator, then parse another unary
operand.

[`checkpoint`](https://docs.rs/rowan/0.17.0/rowan/struct.GreenNodeBuilder.html#method.checkpoint)
marks a child boundary; it isn't a source offset or a copy of the tree.
[`start_node_at`](https://docs.rs/rowan/0.17.0/rowan/struct.GreenNodeBuilder.html#method.start_node_at)
opens a node around children already emitted after that boundary.
`finish_node` closes it, leaving the completed binary node as one child
of the original container.

For `8 / 4 / 2`, imagine the builder's expression children at each step
(trivia is kept too, but omitted from this outline):

```text title="Reuse the same checkpoint to fold left"
checkpoint → Number(8)
checkpoint → Number(8), Slash, Number(4)
checkpoint → Binary(8 / 4)
checkpoint → Binary(8 / 4), Slash, Number(2)
checkpoint → Binary((8 / 4) / 2)
```

The checkpoint remains before the entire growing left expression. We use
it within the same open container; child groups finish their own nodes
before returning. We don't reuse a checkpoint after closing its container.
Rowan's checkpoint is `Copy`, so passing it to one wrap doesn't consume
our saved position.

We wait until the right operand succeeds **and** the new height fits
before wrapping. A height failure uses the saved operator's range, because
the cursor may already be past the right operand. Both sides contribute
to `max`, including a tall right-hand factor in the additive rule below.

Change `expression` to delegate to `factor` for this first endpoint:


## Put addition around factors

Insert `term` **between `expression` and `factor`**:

```rust title="rlox/crates/syntax/src/cst.rs · insert term"
    fn term(&mut self, nesting: usize) -> Result<usize, ParseError> {
        self.eat_trivia();
        let checkpoint = self.builder.checkpoint();
        let mut height = self.factor(nesting)?;

        while let Some(operator) = self.peek_non_trivia() {
            if !matches!(operator.kind, SyntaxKind::Plus | SyntaxKind::Minus) {
                break;
            }
            self.eat_trivia();
            self.bump();
            let right_height = self.factor(nesting)?;
            let next_height = 1 + height.max(right_height);
            if nesting + next_height > MAX_NESTING {
                return Err(ParseError {
                    message: "expression nesting limit exceeded".to_owned(),
                    range: operator.range,
                });
            }
            self.builder
                .start_node_at(checkpoint, SyntaxKind::BinaryExpr.into_raw());
            self.builder.finish_node();
            height = next_height;
        }

        Ok(height)
    }
```

The mechanism is the same, but the operands are complete factors and the
operators are `+` or `-`. Thus `1 + 2 * 3` finishes its right factor
`2 * 3` before wrapping the sum. Both loops fold left, so `8 - 3 - 1`
wraps the first subtraction as the left operand of the second.

Route `expression` through this outer rule:

```diff title="rlox/crates/syntax/src/cst.rs · additive entry"
     fn expression(&mut self, nesting: usize) -> Result<usize, ParseError> {
-        self.factor(nesting)
+        self.term(nesting)
     }
```

The final grammar is the arithmetic subset we already recognize with the
owned parser:

```text
expression → term
term       → factor (("+" | "-") factor)*
factor     → unary (("*" | "/") unary)*
unary      → "-" unary | primary
primary    → NUMBER | "(" expression ")"
```

Both rules leave trivia alone when the next significant token isn't their
operator. On success, the enclosing group or public entry consumes that
trailing trivia. Text between operands is inside the binary wrapper;
outer leading and trailing trivia stays outside it. The comparison's
spelling/comment example lets you inspect this boundary.

## Keep failures lossless before adding recovery

For `1 +`, the left number, space and plus have been emitted when the
right operand fails at EOF. We haven't called `start_node_at` yet, so
those pieces remain siblings in their current container. The root still
reconstructs `1 +`, accompanied by an error at `[3..3)`.

This extends our first-error policy: completed expressions stay as nodes,
but an unfinished binary span isn't wrapped yet. On an error inside a
group or unary operand, those enclosing nodes still close normally. The
public entry then retains the remaining suffix in the root. A height
failure also leaves the emitted pieces unwrapped rather than constructing
a binary node taller than the limit. We'll refine local recovery later;
we don't invent an operand or a token here.

```rust title="rlox/crates/syntax/src/cst.rs · complete-expression projection and infix tests"
    fn shape(node: &SyntaxNode) -> String {
        match node.kind() {
            SyntaxKind::NumberExpr => node.to_string(),
            SyntaxKind::GroupingExpr => {
                format!("(group {})", shape(&node.first_child().expect("operand")))
            }
            SyntaxKind::UnaryExpr => {
                format!("(- {})", shape(&node.first_child().expect("operand")))
            }
            SyntaxKind::BinaryExpr => {
                let mut operands = node.children();
                let left = operands.next().expect("left operand");
                let right = operands.next().expect("right operand");
                let operator = node
                    .children_with_tokens()
                    .filter_map(|element| element.into_token())
                    .find(|token| {
                        matches!(
                            token.kind(),
                            SyntaxKind::Plus
                                | SyntaxKind::Minus
                                | SyntaxKind::Star
                                | SyntaxKind::Slash

                    .expect("operator");
                format!("({} {} {})", operator.text(), shape(&left), shape(&right))
```

`shape` is a test-only readable projection of complete trees. It follows
node children and reads direct operator tokens; it doesn't parse source,
allocate a second AST or evaluate anything. It deliberately expects full
operands, so we use it only after checking that errors are empty. The
source-preservation and partial-input tests don't make that assumption.

The structure cases check precedence, association, both roles of minus,
and the Chapter 10 example against known prefix shapes. The spelling test
checks that leading/trailing trivia stays in the root while comments and
raw numbers remain in the expression. The resource cases check both
folds, both operand heights and enclosing group/unary wrappers. In each
rejected input we retain all source and locate the operator whose parent
would exceed the budget.

```rust title="rlox/crates/syntax/src/lib.rs · complete resulting file"
pub struct Token {

    pub range: TextRange,

pub fn scan(source: &str) -> Result<Vec<Token>, SourceTooLarge> {
    checked_size(source.len())?;
    let mut tokens = Vec::new();

    for (result, span) in SyntaxKind::lexer(source).spanned() {
        let kind = match result {
            Ok(kind) => kind,
            Err(()) => SyntaxKind::Error,
        };
        let range = checked_range(
            checked_size(span.start).expect("validated source length"),
            checked_size(span.end).expect("validated source length"),
        )
        .expect("Logos spans are ordered");

        tokens.push(Token { kind, range });
    }

    Ok(tokens)
}
```

```rust title="rlox/crates/syntax/src/cst.rs · complete resulting file"
pub fn parse(source: &str) -> Result<Parse, SourceTooLarge> {
    let mut parser = Parser::new(source)?;
    parser.builder.start_node(SyntaxKind::Root.into_raw());
    let mut errors = Vec::new();
    match parser.expression(0) {
        Err(error) => errors.push(error),
        Ok(_) => {
            parser.eat_trivia();
            if parser.peek().is_some() {
                errors.push(parser.error("expected end of input"));
            }
        }
    }

    while parser.current < parser.tokens.len() {
        parser.bump();
    }
    parser.builder.finish_node();
    let root = SyntaxNode::new_root(parser.builder.finish());
    Ok(Parse { root, errors })
}

        }
    }

    fn error(&self, message: &str) -> ParseError {
        match self.peek() {
            Some(token) => ParseError {
                message: if token.kind == SyntaxKind::Error {
                    "invalid token".to_owned()
                } else {
                    message.to_owned()
                },
                range: token.range,
            },
            None => {
                let end = checked_size(self.source.len()).expect("validated source length");
                ParseError {
                    message: message.to_owned(),
                    range: checked_range(end, end).expect("ordered EOF range"),
                }
            }
        }
    }

    fn expression(&mut self, nesting: usize) -> Result<usize, ParseError> {
        self.term(nesting)
    }

    fn term(&mut self, nesting: usize) -> Result<usize, ParseError> {
        self.eat_trivia();
        let checkpoint = self.builder.checkpoint();
        let mut height = self.factor(nesting)?;

        while let Some(operator) = self.peek_non_trivia() {
            if !matches!(operator.kind, SyntaxKind::Plus | SyntaxKind::Minus) {
                break;
            }
            self.eat_trivia();
            self.bump();
            let right_height = self.factor(nesting)?;
            let next_height = 1 + height.max(right_height);
            if nesting + next_height > MAX_NESTING {
                return Err(ParseError {
                    message: "expression nesting limit exceeded".to_owned(),
                    range: operator.range,
                });
            }
            self.builder
                .start_node_at(checkpoint, SyntaxKind::BinaryExpr.into_raw());
            self.builder.finish_node();
            height = next_height;
        }

        Ok(height)
    }

    fn factor(&mut self, nesting: usize) -> Result<usize, ParseError> {
        self.eat_trivia();
        let checkpoint = self.builder.checkpoint();
        let mut height = self.unary(nesting)?;

        while let Some(operator) = self.peek_non_trivia() {
            if !matches!(operator.kind, SyntaxKind::Star | SyntaxKind::Slash) {
                break;
            }
            self.eat_trivia();
            self.bump();
            let right_height = self.unary(nesting)?;
            let next_height = 1 + height.max(right_height);
            if nesting + next_height > MAX_NESTING {
                return Err(ParseError {
                    message: "expression nesting limit exceeded".to_owned(),
                    range: operator.range,
                });
            }
            self.builder
                .start_node_at(checkpoint, SyntaxKind::BinaryExpr.into_raw());
            self.builder.finish_node();
            height = next_height;
        }

        Ok(height)
    }

    fn unary(&mut self, nesting: usize) -> Result<usize, ParseError> {
        self.eat_trivia();
        match self.peek() {
            Some(token) if token.kind == SyntaxKind::Minus => {
                if nesting >= MAX_NESTING {
                    return Err(self.error("expression nesting limit exceeded"));
                }
                self.builder.start_node(SyntaxKind::UnaryExpr.into_raw());
                self.bump();
                let result = self.unary(nesting + 1);
                self.builder.finish_node();
                result.map(|height| height + 1)
            }
            _ => self.primary(nesting),
        }
    }

    fn primary(&mut self, nesting: usize) -> Result<usize, ParseError> {
        match self.peek() {
            Some(token) if token.kind == SyntaxKind::Number => {
                self.builder.start_node(SyntaxKind::NumberExpr.into_raw());
                self.bump();
                self.builder.finish_node();
                Ok(0)
            }
            Some(token) if token.kind == SyntaxKind::LeftParen => self.group(nesting),
            _ => Err(self.error("expected an expression")),
        }
    }

    fn group(&mut self, nesting: usize) -> Result<usize, ParseError> {
        if nesting >= MAX_NESTING {
            return Err(self.error("expression nesting limit exceeded"));
        }
        self.builder.start_node(SyntaxKind::GroupingExpr.into_raw());
        self.bump();
        let result = match self.expression(nesting + 1) {
            Err(error) => Err(error),
            Ok(inner_height) => {
                self.eat_trivia();
                match self.peek() {
                    Some(token) if token.kind == SyntaxKind::RightParen => {
                        self.bump();
                        Ok(inner_height + 1)
                    }
                    _ => Err(self.error("expected ')'")),
                }
            }
        };
        self.builder.finish_node();
        result
    }
}

    fn shape(node: &SyntaxNode) -> String {
        match node.kind() {
            SyntaxKind::NumberExpr => node.to_string(),
            SyntaxKind::GroupingExpr => {
                format!("(group {})", shape(&node.first_child().expect("operand")))
            }
            SyntaxKind::UnaryExpr => {
                format!("(- {})", shape(&node.first_child().expect("operand")))
            }
            SyntaxKind::BinaryExpr => {
                let mut operands = node.children();
                let left = operands.next().expect("left operand");
                let right = operands.next().expect("right operand");
                let operator = node
                    .children_with_tokens()
                    .filter_map(|element| element.into_token())
                    .find(|token| {
                        matches!(
                            token.kind(),
                            SyntaxKind::Plus
                                | SyntaxKind::Minus
                                | SyntaxKind::Star
                                | SyntaxKind::Slash
                        )
                    })
                    .expect("operator");
                format!("({} {} {})", operator.text(), shape(&left), shape(&right))
            }
            kind => panic!("unexpected complete expression kind: {kind:?}"),
        }
    }
```
