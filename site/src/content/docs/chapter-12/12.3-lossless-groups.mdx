Our token tree can reconstruct ` ( 001.50 ) `, but its parentheses are
siblings of the number node. It doesn't yet tell us that the parentheses
form a group. We need grammar rules to choose which tokens belong inside
which nodes.

We'll start the concrete parser with numbers and groups. Its tree should
keep the exact spelling while exposing the group as a parent:

```text title="Every byte belongs to a token; nodes group those tokens"
Root [0..12)
  Whitespace [0..1) " "
  GroupingExpr [1..11)
    LeftParen [1..2) "("
    Whitespace [2..3) " "
    NumberExpr [3..9)
      Number [3..9) "001.50"
    Whitespace [9..10) " "
    RightParen [10..11) ")"
  Whitespace [11..12) " "
```

There is another requirement: `(12.5` is incomplete, but an editor still
needs a tree for the characters that exist. A syntax error will accompany
the tree instead of replacing it. We'll stop at the first error for now,
finish any open nodes, and keep the remaining tokens at the root.

Start from [12.2](/chapter-12/12.2-lossless-tree/), in the **Rust workspace
directory**. The existing arithmetic parser and the small `token_tree`
example stay in place. Our new parser will live in `cst`, so its limited
grammar is explicit while we migrate one rule at a time.

```rust title="rlox/crates/syntax/src/cst.rs · imports and result"
use rowan::GreenNodeBuilder;

use crate::parser::ParseError;
use crate::tree::SyntaxNode;
use crate::{SyntaxKind, Token, scan};

const MAX_NESTING: usize = 64;

#[derive(Debug)]
pub struct Parse {
    pub root: SyntaxNode,
    pub errors: Vec<ParseError>,
}
```

`Parse` keeps a tree and located errors together. We reuse the existing
`ParseError` record: its message and range don't depend on an owned
`Expr`. This parser emits concrete nodes instead of allocating expression
boxes. Its error list will contain zero or one error at this step.

The public function will return `Result<Parse, SourceTooLarge>`. An input
that can't fit our byte coordinates still fails before parsing. Ordinary
syntax errors fit those coordinates and leave a useful `Parse`, including
its root. Callers must inspect `errors` to decide whether syntax succeeded;
`Ok` alone means the input was representable.

Append this private state and its implementation block to **`cst.rs`**:

```rust title="rlox/crates/syntax/src/cst.rs · cursor and builder state"
struct Parser<'src> {
    source: &'src str,
    tokens: Vec<Token>,
    current: usize,
    builder: GreenNodeBuilder<'static>,
}

impl<'src> Parser<'src> {
    fn new(source: &'src str) -> Result<Self, SourceTooLarge> {
        Ok(Self {
            source,
            tokens: scan(source)?,
            current: 0,
            builder: GreenNodeBuilder::new(),
        })
    }

    fn peek(&self) -> Option<Token> {
        self.tokens.get(self.current).copied()
    }

    fn bump(&mut self) {
        let token = self.tokens[self.current];
        let spelling = slice(self.source, token.range).expect("scanner ranges are valid");
        self.builder.token(token.kind.into_raw(), spelling);
        self.current += 1;
    }

    fn eat_trivia(&mut self) {
        while let Some(token) = self.peek() {
            if !matches!(token.kind, SyntaxKind::Whitespace | SyntaxKind::LineComment) {
                break;
            }
            self.bump();
        }
    }

    fn error(&self, message: &str) -> ParseError {
        match self.peek() {
            Some(token) => ParseError {
                message: if token.kind == SyntaxKind::Error {
                    "invalid token".to_owned()
                } else {
                    message.to_owned()
                },
                range: token.range,
            },
            None => {
                let end = checked_size(self.source.len()).expect("validated source length");
                ParseError {
                    message: message.to_owned(),
                    range: checked_range(end, end).expect("ordered EOF range"),
                }
            }
        }
    }
}
```

Unlike the owned parser's constructor, `new` keeps every token. `peek`
looks at the current token without skipping anything. `bump` writes that
token's exact spelling into the currently open builder node, then advances
once. A token is emitted exactly when the cursor passes it.

`GreenNodeBuilder::new` owns its cache. The builder's `<'static>` parameter
means it doesn't borrow an external cache; it doesn't require `source` to
be a static string. The source has the separate `'src` lifetime already
familiar from our parser. See the [builder constructor](https://docs.rs/rowan/0.17.0/rowan/struct.GreenNodeBuilder.html#method.new)
and Rust Book's [lifetime discussion](https://doc.rust-lang.org/book/ch10-03-lifetime-syntax.html#the-static-lifetime).

`eat_trivia` advances through whitespace and line comments using the same
emission path. It never discards them. We'll call it at explicit grammar
boundaries rather than hiding it inside lookahead. The `error` helper
locates the current token, classifies lexical `Error` tokens, or creates an
empty range at EOF without inventing token text.

There are now two stacks to follow. Rust's call stack records which grammar
rule is waiting for which child. Rowan's builder stack records which syntax
node receives the next token. A parser method can fail while a Rowan node is
still open. Save that result, close the node, and only then return the failure:
leaving a grammar call must not strand its tree container.

## Let the grammar open and close nodes

Our grammar starts with the same two choices introduced in Chapter 11:

```text
expression → NUMBER | "(" expression ")"
```

This is only the concrete parser's current grammar. Unary and infix rules
remain in the owned arithmetic parser; we'll migrate them in following
sections. Rowan stores the nodes we ask for. It doesn't choose grammar
rules for us, as the [recursive-descent discussion in Crafting Interpreters](https://craftinginterpreters.com/parsing-expressions.html#recursive-descent-parsing)
helps explain.

Before adding the rules, decide where trivia belongs. Leading and trailing
source trivia belongs to `Root`. Inside parentheses, trivia before or after
the operand belongs to `GroupingExpr`. A `NumberExpr` contains just its
number token. That policy gives the byte tree at the start of this section:
spaces around the number remain siblings of its node inside the group.

Insert these methods **inside `impl Parser`, after `error` and before the
implementation's closing brace**:

```rust title="rlox/crates/syntax/src/cst.rs · append grammar methods inside impl"
    fn expression(&mut self, nesting: usize) -> Result<(), ParseError> {
        self.eat_trivia();
        match self.peek() {
            Some(token) if token.kind == SyntaxKind::Number => {
                self.builder.start_node(SyntaxKind::NumberExpr.into_raw());
                self.bump();
                self.builder.finish_node();
                Ok(())
            }
            Some(token) if token.kind == SyntaxKind::LeftParen => self.group(nesting),
            _ => Err(self.error("expected an expression")),
        }
    }

    fn group(&mut self, nesting: usize) -> Result<(), ParseError> {
        if nesting >= MAX_NESTING {
            return Err(self.error("expression nesting limit exceeded"));
        }
        self.builder.start_node(SyntaxKind::GroupingExpr.into_raw());
        self.bump();
        let result = match self.expression(nesting + 1) {
            Err(error) => Err(error),
            Ok(()) => {
                self.eat_trivia();
                match self.peek() {
                    Some(token) if token.kind == SyntaxKind::RightParen => {
                        self.bump();
                        Ok(())
                    }
                    _ => Err(self.error("expected ')'")),
                }
            }
        };
        self.builder.finish_node();
        result
    }
```

`expression` emits leading trivia into the current container, then chooses
a number or a group. A number opens its node, emits its token and closes
the node. It keeps `001.50` as text; it doesn't convert it to `f64`.

A group opens its node before consuming `(`. It asks `expression` to build
the operand inside it, then looks for `)`. The existing budget still allows
64 nested group wrappers and reports the next opening parenthesis as the
limit error. We check that before opening another node or recursing.

There is one consequential difference from our owned parser: **a failing
child cannot bypass the matching `finish_node`**. We save the child's
result in `result`, close the grouping node, and only then return that
result. We deliberately don't use `?` immediately after opening the group;
that would return early with an unclosed node. This follows the same
[Result control flow](https://doc.rust-lang.org/book/ch09-02-recoverable-errors-with-result.html#propagating-errors)
we already use, with builder balance as an extra responsibility.

For `(12.5`, the number node finishes, the group reports a missing close
at EOF, and the group still finishes. Its text is the five bytes `(12.5`.
We haven't fabricated a `)` token to make the tree look complete.

## Finish the root even after an error

Insert this public function **after `Parse` and before `struct Parser`**
in **`cst.rs`**:

```rust title="rlox/crates/syntax/src/cst.rs · public entry point"
pub fn parse(source: &str) -> Result<Parse, SourceTooLarge> {
    let mut parser = Parser::new(source)?;
    parser.builder.start_node(SyntaxKind::Root.into_raw());
    let mut errors = Vec::new();
    match parser.expression(0) {
        Err(error) => errors.push(error),
        Ok(()) => {
            parser.eat_trivia();
            if parser.peek().is_some() {
                errors.push(parser.error("expected end of input"));
            }
        }
    }

    while parser.current < parser.tokens.len() {
        parser.bump();
    }
    parser.builder.finish_node();
    let root = SyntaxNode::new_root(parser.builder.finish());
    Ok(Parse { root, errors })
}
```

The function opens one root around the whole operation. After a successful
expression, it consumes trailing trivia and rejects a leftover non-trivia
token. On either kind of syntax failure it records the first error. Once
the expression rule returns, all its group nodes are closed.

The final loop emits every remaining token directly into `Root`. It
advances the cursor on every iteration, so it can't retry the same failing
token indefinitely. Finally we close the root and create its red handle.
Even empty or malformed input has a balanced tree covering the source.

Consider `(1 @)`. The group has already consumed `(1 ` when `@` prevents
it from finding its close. The partial group finishes, and the suffix is
kept outside it:

```text title="First-error policy: close the partial group, then keep the suffix"
Root [0..5)
  GroupingExpr [0..3) "(1 "
  Error [3..4) "@"
  RightParen [4..5) ")"
error: invalid token [3..4)
```

The group still contains its opening parenthesis, number node and space;
this outline abbreviates those children to show the boundary. The root
reconstructs `(1 @)` exactly. We aren't resuming the grammar or attaching
that suffix back to the group yet. Keeping it visible is the first step
toward recovery, which we'll refine after the arithmetic rules are in place.

```rust title="rlox/crates/syntax/examples/parse_cst.rs · complete initial file"
fn main() {
```

```rust title="rlox/crates/syntax/src/lib.rs · complete resulting file"
pub fn scan(source: &str) -> Result<Vec<Token>, SourceTooLarge> {
    checked_size(source.len())?;
    let mut tokens = Vec::new();

    for (result, span) in SyntaxKind::lexer(source).spanned() {
        let kind = match result {
            Ok(kind) => kind,
            Err(()) => SyntaxKind::Error,
        };
        let range = checked_range(
            checked_size(span.start).expect("validated source length"),
            checked_size(span.end).expect("validated source length"),
        )
        .expect("Logos spans are ordered");

        tokens.push(Token { kind, range });
    }

    Ok(tokens)
```

```rust title="rlox/crates/syntax/src/cst.rs · complete resulting file"
pub struct Parse {
    pub root: SyntaxNode,
    pub errors: Vec<ParseError>,

pub fn parse(source: &str) -> Result<Parse, SourceTooLarge> {
    let mut parser = Parser::new(source)?;
    parser.builder.start_node(SyntaxKind::Root.into_raw());
    let mut errors = Vec::new();
    match parser.expression(0) {
        Err(error) => errors.push(error),
        Ok(()) => {
            parser.eat_trivia();
            if parser.peek().is_some() {
                errors.push(parser.error("expected end of input"));
            }
        }
    }

    while parser.current < parser.tokens.len() {
        parser.bump();
    }
    parser.builder.finish_node();
    let root = SyntaxNode::new_root(parser.builder.finish());
    Ok(Parse { root, errors })
}

struct Parser<'src> {
    source: &'src str,
    tokens: Vec<Token>,
    current: usize,
    builder: GreenNodeBuilder<'static>,
}

impl<'src> Parser<'src> {
    fn new(source: &'src str) -> Result<Self, SourceTooLarge> {
        Ok(Self {
            source,
            tokens: scan(source)?,
            current: 0,
            builder: GreenNodeBuilder::new(),
        })
    }

    fn peek(&self) -> Option<Token> {
        self.tokens.get(self.current).copied()
    }

    fn bump(&mut self) {
        let token = self.tokens[self.current];
        let spelling = slice(self.source, token.range).expect("scanner ranges are valid");
        self.builder.token(token.kind.into_raw(), spelling);
        self.current += 1;
    }

    fn eat_trivia(&mut self) {
        while let Some(token) = self.peek() {
            if !matches!(token.kind, SyntaxKind::Whitespace | SyntaxKind::LineComment) {
                break;
            }
            self.bump();
        }
    }

    fn error(&self, message: &str) -> ParseError {
        match self.peek() {
            Some(token) => ParseError {
                message: if token.kind == SyntaxKind::Error {
                    "invalid token".to_owned()
                } else {
                    message.to_owned()
                },
                range: token.range,
            },
            None => {
                let end = checked_size(self.source.len()).expect("validated source length");
                ParseError {
                    message: message.to_owned(),
                    range: checked_range(end, end).expect("ordered EOF range"),
                }
            }
        }
    }

    fn expression(&mut self, nesting: usize) -> Result<(), ParseError> {
        self.eat_trivia();
        match self.peek() {
            Some(token) if token.kind == SyntaxKind::Number => {
                self.builder.start_node(SyntaxKind::NumberExpr.into_raw());
                self.bump();
                self.builder.finish_node();
                Ok(())
            }
            Some(token) if token.kind == SyntaxKind::LeftParen => self.group(nesting),
            _ => Err(self.error("expected an expression")),
        }
    }

    fn group(&mut self, nesting: usize) -> Result<(), ParseError> {
        if nesting >= MAX_NESTING {
            return Err(self.error("expression nesting limit exceeded"));
        }
        self.builder.start_node(SyntaxKind::GroupingExpr.into_raw());
        self.bump();
        let result = match self.expression(nesting + 1) {
            Err(error) => Err(error),
            Ok(()) => {
                self.eat_trivia();
                match self.peek() {
                    Some(token) if token.kind == SyntaxKind::RightParen => {
                        self.bump();
                        Ok(())
                    }
                    _ => Err(self.error("expected ')'")),
                }
            }
        };
        self.builder.finish_node();
        result
    }
```
